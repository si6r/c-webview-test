# WebView-тест доставки (iOS / TikTok)

Цель: воспроизвести «белый экран» в встроенном браузере TikTok и проверить, виноват ли сложный iframe. Прод и код проекта не трогаются.

Файлы: `index.html` (меню), `complex.html` (как в cubbbe), `simple.html` (как у конкурентов), `offer.html` / `white.html` (контент), `config.js` (1 строка — твой логгер), `harness.js` (маячок + экранный лог).

---

## Шаг 1. Логгер (1 минута)

1. На компьютере открой **https://webhook.site** → скопируй **Your unique URL**.
2. Открой `config.js`, замени `https://webhook.site/REPLACE-ME` на свой URL.

Если пропустить — тесты всё равно работают, но без записи на компьютере (только чёрная панель на телефоне).

## Шаг 2. Залить на GitHub Pages (3 минуты)

1. Создай репозиторий на GitHub (можно приватным он быть не может — Pages нужен public, либо отдельный публичный репо только под этот тест).
2. Загрузи все файлы из папки `webview-test` в корень репо (кнопка **Add file → Upload files**).
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main` / `/ (root)` → Save**.
4. Через ~1 минуту вверху появится ссылка вида `https://ТВОЙ-НИК.github.io/ИМЯ-РЕПО/`.

Проверь её сначала **в обычном Safari** на iPhone — должны открываться зелёный «ОФФЕР ВИДЕН» в обоих тестах (это контроль: «в Chrome норм»).

## Шаг 3. Открыть ВНУТРИ приложения TikTok (iOS)

Встроенный браузер TikTok = WKWebView — та самая среда. Способы открыть ссылку внутри него:

- **Через bio:** профиль → Edit profile → Website → вставь ссылку на `index.html` → сохрани → тапни по ней из своего профиля. Откроется in-app браузер TikTok.
- **Через личку:** отправь ссылку себе в Direct Messages TikTok → тапни.

Когда меню открылось внутри TikTok — жми **ТЕСТ 1**, смотри результат, вернись, жми **ТЕСТ 2**.

## Шаг 4. Как читать результат

Смотри **чёрную панель сверху** (на телефоне) и **webhook.site** (на компьютере).

| Что видишь | Вывод |
|---|---|
| Зелёный «ОФФЕР ВИДЕН ✅» + строка `offer:rendered` | доставка сработала |
| Белый экран, панель замерла на `…appended`, потом `TIMEOUT-4s-NO-LOAD`, и **нет** `offer:rendered` | баг воспроизведён |
| `complex:EXCEPTION ...` | сам Shadow DOM упал — точная причина в тексте ошибки |

**Главный вывод — сравнение двух тестов:**
- ТЕСТ 1 = белый экран, ТЕСТ 2 = оффер → **причина в сложном iframe** (Shadow DOM/postMessage). Фикс — перейти на простой iframe.
- Оба показали оффер → на iOS рендер не виноват; потеря, вероятно, Android-специфична или связана не с iframe (таймаут API / cookie / PRG). Тогда следующий шаг — тест на Android и/или логгер на стороне API.

## Шаг 5 (по желанию). Проверка cross-origin

По умолчанию оффер — с того же домена. В реальном клоаке оффер на **другом** домене (важно для iOS из-за ITP). Чтобы проверить:

1. Залей `offer.html` на второй бесплатный хостинг (например, перетащи файл на https://app.netlify.com/drop → получишь `https://что-то.netlify.app`).
2. Открой тест с параметром: `…/complex.html?offer=https://что-то.netlify.app/offer.html`

Если same-origin работает, а cross-origin даёт белый экран → дело в межсайтовых ограничениях WebView, а не в самом рендере.
